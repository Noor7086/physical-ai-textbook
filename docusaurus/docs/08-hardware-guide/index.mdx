# Hardware Guide

Building physical AI systems requires the right hardware foundation. Whether you are running neural network inference, simulating humanoid locomotion in Gazebo, or deploying models to edge devices, your hardware choices directly impact development speed, iteration cycles, and the complexity of problems you can tackle.

This guide walks you through every hardware decision you need to make -- from your development workstation to embedded compute platforms and robot hardware itself.

## Learning Objectives

By the end of this module, you will be able to:

1. **Select** appropriate hardware for your budget and learning goals
2. **Configure** a development workstation with GPU acceleration for robotics AI
3. **Set up** an NVIDIA Jetson device for edge deployment of perception and control models
4. **Evaluate** robot platforms ranging from simulation-only to full humanoid systems
5. **Understand** the compute pipeline from training workstation to on-robot inference
6. **Budget** realistically for a physical AI development lab at each tier

## Why Hardware Matters in Physical AI

Traditional software development can happen on nearly any laptop. Physical AI is different. Consider the computational demands across the development pipeline:

```
┌─────────────────────────────────────────────────────────────────┐
│                   Physical AI Compute Pipeline                  │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌──────────┐    ┌──────────────┐    ┌───────────────────────┐  │
│  │ TRAINING │    │  SIMULATION  │    │  REAL-TIME INFERENCE   │  │
│  │          │    │              │    │                        │  │
│  │ Cloud or │───▶│ Workstation  │───▶│  Edge Device (Jetson)  │  │
│  │ HPC GPU  │    │ GPU + CPU    │    │  or On-Robot Compute   │  │
│  │          │    │              │    │                        │  │
│  │ Hours to │    │ Real-time    │    │  <10ms latency         │  │
│  │ Days     │    │ physics      │    │  required              │  │
│  └──────────┘    └──────────────┘    └───────────────────────┘  │
│                                                                 │
│  High VRAM           Balanced             Low Power, Low        │
│  High Throughput     GPU + CPU            Latency               │
└─────────────────────────────────────────────────────────────────┘
```

Each stage in this pipeline has distinct hardware requirements. A model trained in the cloud on A100 GPUs must ultimately run on a Jetson Orin embedded in a robot's torso -- and do so within a strict latency budget.

## Budget Considerations

### Where to Invest First

If you are building incrementally, prioritize your spending in this order:

1. **GPU (highest priority)** -- The single most impactful component. VRAM determines the size of models you can train and the complexity of simulations you can run. A 12 GB card is the practical minimum for modern robotics AI workloads.

2. **RAM** -- Simulation environments like Gazebo and Isaac Sim are memory-hungry. 16 GB is the floor; 32 GB gives comfortable headroom.

3. **CPU** -- Multi-core performance matters for ROS 2 (which runs many concurrent nodes) and for physics simulation stepping. Aim for 8+ cores.

4. **Storage** -- Isaac Sim alone requires ~30 GB installed. Docker images, datasets, and ROS packages add up fast. NVMe speed matters for loading large simulation assets.

5. **Edge device** -- A Jetson is not required until you are ready to deploy models off your workstation. It can be added later.

### Cost-Saving Strategies

```python
# Quick cost estimator for your physical AI lab
def estimate_lab_cost(tier: str) -> dict:
    """Estimate costs for a physical AI development setup."""
    tiers = {
        "beginner": {
            "workstation": 800,
            "edge_device": 0,
            "robot": 0,
            "peripherals": 50,
            "cloud_monthly": 0,
        },
        "intermediate": {
            "workstation": 1500,
            "edge_device": 500,
            "robot": 1100,
            "peripherals": 200,
            "cloud_monthly": 50,
        },
        "advanced": {
            "workstation": 3000,
            "edge_device": 900,
            "robot": 16000,
            "peripherals": 500,
            "cloud_monthly": 200,
        },
    }

    config = tiers.get(tier, tiers["beginner"])
    config["total_upfront"] = sum(
        v for k, v in config.items() if k != "cloud_monthly"
    )
    config["first_year_total"] = (
        config["total_upfront"] + config["cloud_monthly"] * 12
    )
    return config

# Example usage
for tier in ["beginner", "intermediate", "advanced"]:
    costs = estimate_lab_cost(tier)
    print(f"{tier.upper()}: ${costs['total_upfront']:,} upfront, "
          f"${costs['first_year_total']:,} first year")
```

**Output:**
```
BEGINNER: $850 upfront, $850 first year
INTERMEDIATE: $3,300 upfront, $3,900 first year
ADVANCED: $20,400 upfront, $22,800 first year
```

**Tips for reducing costs:**
- Use Google Colab or Lambda Labs for GPU training bursts instead of buying a top-tier GPU
- Buy previous-generation GPUs (RTX 3090 offers 24 GB VRAM at lower cost than a 4090)
- Start with simulation-only (Tier 1) and add physical hardware as your skills grow
- University labs and makerspaces often have shared Jetson devices and robots
